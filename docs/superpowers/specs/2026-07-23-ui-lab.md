# UI Lab and Portfolio Density Redesign

- **Status:** Approved for planning; implementation deferred
- **Date:** 2026-07-23
- **Related decision:** ADR 001, Astro with Svelte portfolio islands

## Purpose

Expand `/ui-lab` into a development-only workbench for testing component states,
collection layouts, content density, responsive behavior, and paper/ink palettes.
Approved experiments may later be promoted into a shorter, multi-page portfolio.

The lab must use production components directly. It is not a parallel demo system.
Fixtures, adapters, and lab-only controls may differ, but promoted components and
view models remain shared with production.

## Goals

1. Compare project, blog, and skill collections as grids, tables, rows, compact
   lists, and constrained showcases.
2. Tune width, height, spacing, alignment, borders, color, icon placement, text
   lists, and overflow behavior without editing component source for each trial.
3. Test deterministic edge cases and optionally preview live vault content.
4. Support filtering, sorting, searching, and accessible temporary reordering.
5. Add project details with Markdown, images, and safe embedded video.
6. Reduce the landing page from eight full sections to a concise index that links
   to dedicated content pages.
7. Widen blog articles and reorganize the about/toolbox presentation.
8. Evolve the current paper theme into a rustic but refined family of subtle
   off-white stocks and warm inks.

## Non-goals

- Publishing `/ui-lab` as part of the public portfolio.
- Replacing Astro, the vault CMS, or Astro content collections.
- Loading the React simulation engine on portfolio routes.
- Persisting visitor drag order back into the vault.
- Allowing arbitrary iframe HTML from Markdown or frontmatter.
- Promoting an experiment automatically without human visual review.

## Lab information architecture

The desktop lab retains a split inspector and preview. Mobile stacks the inspector
above the preview. The inspector is divided into focused tabs instead of one long
control list:

1. **Data** — fixture/live source, edge-case scenario, search, tags, status.
2. **Layout** — view mode, columns, minimum item width, container width.
3. **Density** — gaps, padding, margins, line height, card height.
4. **Style** — palette, border, shadow, texture, accent assignment.
5. **Content** — visible fields, list markers, summary length, icon position.
6. **Behavior** — sorting, temporary order, overflow, pagination, modal.

Every control set provides Reset and Copy state actions. Experiment state
should be serializable to URL query parameters so a review configuration can
be shared. Local
storage may remember the last state but must not be the only persistence mechanism.

## Collection experiment model

The shared lab model covers:

- View: `grid`, `table`, `rows`, `compact`, or `showcase`.
- Width: narrow, standard, wide, fluid, or an explicit preview width.
- Columns: one through four or responsive `auto-fit`.
- Item sizing: minimum width, maximum width, auto/fixed/clamped height.
- Spacing: outer padding, row gap, column gap, card padding, text spacing.
- Alignment: start, center, end, stretch, and supported justification modes.
- Decoration: border width/style, hard shadow, accent position, paper palette.
- Content: show or hide media, summary, tags, status, links, and metadata.
- Icons: leading, trailing, above, below, or hidden; configurable size and gap.
- Overflow: visible, explicit scroll region, clip with fade and View all, or
  pagination.

Clipped content must never disappear without an affordance. A clipped
showcase shows its hidden-item count and a View all action. Scroll regions are
labelled and keyboard reachable. Table mode uses semantic table markup on
desktop and an equivalent row or
card presentation on narrow screens.

## Sorting, filtering, and ordering

Projects support featured, date, title, status, tag, and custom-order
sorting. Blogs support date, title, tag, and reading-time sorting. Skills
support category, name, and
curated-order sorting.

Filters are multi-select and combine with text search. Active filters are visible,
removable, and represented in the URL. Filtering never mutates source arrays.

Temporary manual ordering is available in the lab through drag handles and keyboard
Move up/Move down controls. Production custom ordering comes from optional vault
frontmatter, not browser state. Featured and curated order remain author-controlled.

## Fixture and live-data policy

Deterministic fixtures are the default and include:

- normal records;
- long titles and descriptions;
- many tags and links;
- missing media;
- mixed project statuses;
- narrow and wide media;
- empty and single-item collections.

Live-vault mode receives build-time normalized data from Astro. The Svelte
lab does not fetch or parse vault files in the browser. Fixtures and live data
implement the
same view-model contracts.

## Project card and detail experience

`ProjectCard` gains controlled density and display variants rather than receiving
lab-specific CSS from its parent. The project collection may render cards, table
rows, compact rows, or a bounded showcase.

Project details use a hybrid model:

- A card links to a canonical `/projects/[slug]` page.
- Client enhancement may open the same content in an accessible modal.
- Direct navigation and no-JavaScript use remain fully functional.
- The modal restores focus, closes with Escape, labels its title and description,
  and does not trap content behind an inaccessible nested scroll area.

Project media uses a typed discriminated model for images, native video, and approved
YouTube/Vimeo embeds. Each item requires an accessible title or alt text. Existing
`cover` and `images` fields remain supported during migration.

## Portfolio information architecture

The current landing page contains eight full sections. The promoted redesign makes
`/` a concise index:

1. Hero and primary navigation.
2. Short about statement with a link to `/about`.
3. Three or four selected projects with a link to `/projects`.
4. Three recent posts with a link to `/blog`.
5. Compact contact/footer.

Dedicated pages own the full content:

- `/about` — biography, toolbox, experience, and education.
- `/projects` — complete filterable/sortable collection.
- `/projects/[slug]` — canonical project details.
- `/blog` and `/blog/[slug]` — archive and article routes.
- `/gallery` — complete gallery.

Production promotion removes the full gallery, toolbox, experience, and education
from the landing page. Section spacing becomes density-token driven rather than
repeating unconditional `py-24` and `mb-12` values.

## Blog reading layout

The current article column is limited to `65ch` beside a `210px` table of contents.
The redesign tests a text measure between approximately `72ch` and `76ch` on wide
screens while retaining a comfortable narrow-screen measure. Code blocks, tables,
diagrams, and media may break out beyond prose width inside the article container.

The table of contents remains sticky only when sufficient width exists. Article
headers, metadata, and variant controls align to the wider reading grid.

## About and toolbox layout

The landing-page about copy becomes one concise statement plus a small fact list.
Detailed biography moves to `/about`.

The toolbox is reorganized into smaller, balanced groups:

- Languages
- Frontend
- Backend
- Data and machine learning
- Infrastructure
- Tools

The lab compares grouped lists, a compact matrix, and a table-like index.
Categories use consistent label widths and spacing. Icons are optional
reinforcement, not the primary organizing device. Color is assigned by
category or meaning rather than by
alternating every badge.

## Rustic paper and ink system

The lab provides related stock presets rather than one generic light theme:

- **Soft Eggshell** — warm cream with brown-black ink.
- **Bone** — pale neutral ivory with restrained charcoal ink.
- **Linen** — fibrous beige with muted oxblood accents.
- **Ledger** — aged grey-cream with faded navy and sage.
- **Cotton** — refined near-white with subtle warm shadows.

Each preset defines paper, raised paper, ink, soft ink, rules, four accents,
and texture strength. Texture uses a low-opacity reusable grain/fiber layer
and must not
reduce text contrast or pointer clarity. Pure black, bright white, heavy distressing,
and novelty torn-paper effects are avoided.

Dark mode remains supported but is evaluated separately from the paper-stock presets.
All final combinations must meet WCAG AA contrast for body text and controls.

## Component boundaries

- Primitives do not import portfolio content or owner configuration.
- Patterns receive normalized view models and controlled variants.
- Collection controllers own search, filters, sort, view selection, and ordering.
- Collection renderers own semantic markup for each view.
- Astro pages adapt content collections and provide live data.
- Svelte owns interactive state and progressive enhancement.
- Palette tokens remain framework-independent CSS custom properties.

## Testing and review strategy

Testing is phased:

1. Vitest, `@testing-library/svelte`, and user-event for state and semantics.
2. axe checks for controls, collection views, modal, and overflow modes.
3. Playwright for responsive view changes, filters, reorder, modal focus, and route
   fallback.
4. Review-only visual snapshots for experiments.
5. CI-blocking snapshots only for stable promoted primitives and patterns.

Every Svelte change follows the repository workflow: list relevant official
sections, retrieve all relevant documentation, and run the Svelte autofixer
until no issues or
suggestions remain.

## Promotion gates

An experiment may move into production only when:

- a human approves its desktop and mobile appearance;
- keyboard and screen-reader behavior is verified;
- deterministic and live-vault modes render the same contract;
- its production route has a no-JavaScript fallback where applicable;
- tests, type checks, lint, formatting, and Astro build pass;
- it does not load Three.js, r3f, or Leva on portfolio routes;
- the change is promoted in a separate, reviewable commit from lab experimentation.

## Acceptance criteria

- `/ui-lab` remains development-only and unlinked from production navigation.
- Projects can be reviewed in all five collection views and responsive widths.
- Layout, density, style, content, and overflow controls are resettable and shareable.
- Project, blog, and skill collections can be searched, filtered, and sorted.
- Temporary project ordering is keyboard accessible.
- A bounded showcase never hides content without a count and View all action.
- Project details support trusted Markdown, images, native video, and approved embeds.
- The landing page contains only the concise index sections defined above.
- Blog article measure is wider without creating excessively long lines on mobile.
- About and toolbox layouts use balanced, meaningful grouping.
- At least five rustic paper presets are available for lab review.
