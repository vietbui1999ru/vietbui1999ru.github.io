# Plan: spec B, library of backlogs

Spec: `SPEC.md` on `feat/garden-b2` (approved 2026-11-26, hash prefix `b7224033`).

## Findings that shape the plan

- `src/content/config.ts` has no `library` collection. The `site` loader reads only `Home.md`, `About.md` and `Focus/*.md`, so `Site/Library.md` is not loaded yet.
- `src/lib/publish/route.ts` has the `library` site slot but no `game`, `book`, `film` or `recipe` folder. `src/lib/publish/validate.ts` has no schema for them, so a library note fails validation today.
- `src/lib/publish/attachments.ts` copies only files embedded in the note body. A frontmatter `cover:` is not copied.
- `pageUrlFor` in `src/lib/publish/preview-diff.ts` maps only blog posts.
- The publish scan copies only `publish: true` notes. So a library draft reaches the site with `publish: true` and `draft: true`. Pages hide drafts in production and show them under `astro dev`.
- No code uses `astro:assets` today. Vault files sit outside `src/`, and Astro resizes only imported images. Plan: copy library covers into a gitignored `src/assets/library/` at build preparation (next to `scripts/copy-vault-images.ts`). Then load them with `import.meta.glob` and `getImage`.
- `buildSiteWikilinkIndex` indexes Blogs, Thoughts and Projects only. Library detail pages need backlinks, so the index must include `Library/`.
- `FeedItem.kind` is `"blog" | "thought"`. `buildFeed(blogs, thoughts, limit)` takes fixed arguments.
- No tabs, progress bar or cover grid primitive exists. `Chip`, `CollectionToolbar` and `filterAndSortCollection` can be reused.
