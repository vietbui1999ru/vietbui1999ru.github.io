# SPEC: Obsidian publishing pipeline (spec D)

## Objective
Write anywhere in the personal vault, mark a note `publish: true`, preview it locally, then publish it to the live garden with one command. The publish logic moves into this repo, routes notes by `type`, and the site renders Typst, Mermaid, Excalidraw, video embeds, cross-type wikilinks with hover previews and backlinks, inside layout presets. Success: `npm run publish -- --dry-run` shows exactly what will change, and `npm run publish` makes it live without a commit to this repo. Context: `docs/superpowers/specs/2026-11-22-digital-garden-pivot.md`. Builds on spec A (`feat/garden-a`).

Fixtures used by the verify lines: `tests/fixtures/personal-vault` (a small source vault with published, unpublished, variant, Excalidraw and private-comment notes) and temporary git repos created inside each test.

## Boundaries
### Always
- Keep publish logic in pure, tested modules under `src/lib/publish/`; `scripts/publish.ts` only wires them
- Read `PERSONAL_VAULT` from the environment (`mise.local.toml` on the owner's machine), never a hard-coded path
- Add new renderers as remark/rehype plugins sharing the hash-keyed SVG cache in `.cache/`
- Run `svelte-autofixer` on every new or changed Svelte component
- Run `~/dotfiles/scripts/spec check SPEC.md` and `~/dotfiles/scripts/floor-guard` before claiming done
### Ask first
- New dependencies other than pele, the typst.ts renderer (`rehype-typst` / `@myriaddreamin/typst-ts-node-compiler`)
- Any write to a real vault (personal vault or PortfolioVault) outside test fixtures, except the TLDR generator creating new `*.tldr.md` drafts in the personal vault
- Removing the `vendor/vault` submodule
### Never
- Write or edit owner content in a real vault (the only exception is creating a new TLDR draft that does not exist yet)
- Call a model from the site build, CI, or tests
- Use an Anthropic API key or add an LLM SDK dependency; the only model access is the owner's Pi login to opencode-go
- Push to this repo's `main` from the publish script
- Fetch remote pages at build time (no link-card scraping)
- Edit a `verify:` line or a test to make a check pass

## Open Questions
- Does `rehype-typst` work with Astro 5's markdown pipeline? Default: spike first; if not, call `@myriaddreamin/typst-ts-node-compiler` from a small custom rehype plugin.
- Excalidraw plugin export file name. Default: `<name>.excalidraw.svg` next to the drawing, the plugin's auto-export default; confirm on the Mac.
- Dispatch token. Default: a fine-grained PAT that can only send a dispatch to this repo, stored as a PortfolioVault Actions secret; the owner creates it.
- PortfolioVault folder per type. Default: `Blogs/`, `Thoughts/`, `Site/`, `Gallery/`, `Portfolio/Projects/` as today; spec B adds `Library/<type>/`.
- TLDR prompt wording and target length. Default: a few sentences plus up to five bullet takeaways, in the post's own voice, written to `post.tldr.md` with the parent's title and `parent_slug`; tune after the first drafts.
- Owner checklist outside this repo: delete the persona variant files (`*.ai.md`, `*.yoda.md` and others) from the personal vault, make sure `pi` is logged in to opencode-go on the machine that runs `npm run publish`, install the obsidian-typst plugin, turn on Excalidraw auto-export SVG, add `PERSONAL_VAULT` to `mise.local.toml`, retire `~/repos/Obsidian/scripts/sync-*.{sh,mjs}` after the first successful publish.
