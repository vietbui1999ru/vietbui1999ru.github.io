# SPEC: Themed dropdown (issue #15)

## Objective
Replace the native `<select>` in the project sort control with a themed, accessible listbox. The open option list must follow the ink-on-paper theme in light and dark, which a native list cannot do. The component is reusable for the library status and tag filters in spec B. Success: the sort control on `/projects` opens a themed list, works by keyboard, mouse and touch, and no native `<select>` remains in `src/components`. Context: issue #15.

## Acceptance Criteria
- AC-1: A pure listbox module computes the next active option for ArrowUp, ArrowDown, Home and End, and clamps at the ends without wrapping
  verify: `npx vitest run tests/lib/listbox.test.ts -t "navigation"`
- AC-2: The listbox module matches type-ahead: typed characters within 500 ms build a prefix, matched case-insensitively from the option after the active one
  verify: `npx vitest run tests/lib/listbox.test.ts -t "type-ahead"`
- AC-3: `InkSelect` renders a button with `aria-haspopup="listbox"` and `aria-expanded`, and a `role="listbox"` popup of `role="option"` items with `aria-selected`; the popup is labelled by the `label` prop
  verify: `npx vitest run tests/components/ink-select.test.ts -t "aria"`
- AC-4: Click on the button, or Enter, Space or ArrowDown on the focused button, opens the list with the current value active
  verify: `npx vitest run tests/components/ink-select.test.ts -t "open"`
- AC-5: In the open list, arrow keys, Home, End and type-ahead move the active option, shown through `aria-activedescendant`
  verify: `npx vitest run tests/components/ink-select.test.ts -t "keyboard"`
- AC-6: Enter, Space or a click on an option calls `onChange` with its value once, closes the list and returns focus to the button
  verify: `npx vitest run tests/components/ink-select.test.ts -t "select"`
- AC-7: Escape, Tab or a pointer press outside the component closes the list without calling `onChange`; Escape returns focus to the button
  verify: `npx vitest run tests/components/ink-select.test.ts -t "close"`
- AC-8: Styling uses theme tokens only: 1.5px ink border, `bg-paper-raised`, mono labels, `shadow-hard-sm`; the component has no hex or rgb color literals
  verify: `! rg -q "#[0-9a-fA-F]{3,8}\b|rgb\(" src/components/primitives/InkSelect.svelte`
- AC-9: `ProjectSortControl` uses `InkSelect`, and no native `<select>` remains in visitor-facing components under `src/components`; the dev-only `/ui-lab` panels (`ui-lab/`, `CollectionToolbar.svelte`) keep native selects
  verify: `rg -q "InkSelect" src/components/patterns/ProjectSortControl.svelte && ! rg -q "<select" src/components -g '!**/ui-lab/**' -g '!**/CollectionToolbar.svelte'`
- AC-10: The project sort behaviour is unchanged: featured first by default, and each sort key still sorts as before
  verify: `npx vitest run tests/components/project-sort.test.ts`
- AC-11: `/ui-lab` shows the sort control fixture built on `InkSelect`
  verify: `rg -q "ProjectSortFixture" src/pages/ui-lab.astro && rg -q "ProjectSortControl" src/components/ui-lab/ProjectSortFixture.svelte`
- AC-12: Existing tests still pass
  verify: `npx vitest run`
  baseline: pass
- AC-13: Lint passes
  verify: `npx oxlint`
  baseline: pass
- AC-14: The open list reads well in light and dark at 375 px and 1280 px; at 375 px it fits the viewport with no horizontal scroll, and touch selection works
  verify: manual - visual and touch check in a browser

## Boundaries
### Always
- Keep keyboard and type-ahead rules in `src/lib/listbox.ts`, free of DOM code, so spec B can reuse them
- Run `svelte-autofixer` on every new or changed Svelte component
- Run `~/dotfiles/scripts/spec check SPEC.md` and `~/dotfiles/scripts/floor-guard` before claiming done
### Ask first
- New dependencies (no headless UI library is expected)
- Changes to the sort keys or the sort order
### Never
- Edit a `verify:` line or a test to make a check pass
- Add multi-select now; keep the option model (`{ value, label }[]`) so it can be added later
- Write site copy

## Open Questions
- The issue asks for a garden block too. A dropdown alone has no page-section use, and blocks are configured from vault frontmatter with no callbacks. Default: `InkSelect` is a primitive only; a block wraps it when a filter section exists (spec B).
- Small screens: the issue allows a full-width sheet. Default: the list matches the button width, grows to fit labels, and is capped at the viewport width minus 32 px. No sheet.
- Name: `InkSelect`, after `InkLink`. Default: keep it.
